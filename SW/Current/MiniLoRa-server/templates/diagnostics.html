What do these fields mean?
FieldMeaning
SeenWhen the server received the frame. The diag goes out after the telemetry of the same wake cycle, so its counters already include that cycle. Diag frames arrive via LoRaWAN (fPort 2) and, when WiFi is configured, also via the server's /diag endpoint.
FWFirmware version the device reported.
BootsTotal boot count — RTC-persistent, survives deep sleep. Also drives the diag cadence (one diag every 16 boots). A RESET_DIAG command keeps this counter.
Unexp. resetsBoots that did not wake from a clean deep sleep — power loss, crash, watchdog, brown-out. Should stay 0; a rising count points at a battery or hardware problem.
GPS toTotal GPS windows that ended without a fix (timed out).
Join failTotal LoRaWAN join failures. A few around firmware updates are normal (dev/nonet salts change); a rising trend means gateway/backhaul trouble or drained keys.
Send failTotal LoRaWAN send failures after a successful join.
WiFiTotal failed WiFi pushes (telemetry or diag) — AP unreachable, wrong credentials, server down.
ZigbeeTotal failed Zigbee publishes (join failures included).
SensorTotal sensor read failures (BME280 / accelerometer). Occasional single hits are benign; every cycle failing = wiring or driver issue.
GPS failsConsecutive GPS failures since the last valid fix — resets to 0 on the next fix. This is the counter the indoor backoff reacts to.
TTFFTime-to-first-fix of the most recent successful GPS window, in seconds (— = no fix since the last reset). Compare against the configured GPS budget (warm 60 s / cold 150 s): a TTFF near the budget means the window was nearly wasted.
MarginLinkCheck margin of the diag uplink, in dB — how much radio-link headroom remains (— / 255 = unknown). Positive is good; ≈0 dB or negative means the gateway barely hears you (antenna/placement problem).
GWGateways that heard the diag uplink (from the same LinkCheck answer).
OTAResult of the last firmware pull: STAGED = valid image downloaded, switches on next reboot · NO SRV = server unreachable · DL FAIL = download error · BAD IMG = SHA-256 mismatch, image rejected (the running firmware is untouched). Blank = no OTA activity.
Power/FlagsRaw powerFlags byte plus decoded chips: LOW BAT = battery below the degraded threshold (3500 mV, non-LoRa radios skipped) · CRIT = below the critical threshold (3300 mV, LoRa only) · OTA = image pending verification · RECOVERY = boot-loop guard active.

All failure counters are cumulative totals since the device last counted them — a RESET_DIAG command (Remote tab → Reset counters, or TTN downlink 4D 03 00) clears everything except the boot count. The exception is GPS fails, which is consecutive by definition.
