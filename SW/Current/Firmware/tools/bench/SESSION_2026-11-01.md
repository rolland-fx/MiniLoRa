## Bugs fixed today

1. **BLE adv not restarted on GATT disconnect** (BleTransport) — NimBLE
   auto-stops a connectable adv; the window stayed open but silent; phone
   actions timed out with Android GATT status 147.
2. **NVS config blob sizing** (Stores) — schema-3 blob is `kConfigSize+3`;
   both buffers were `+1`: save smashed 2 stack bytes, load rejected every
   save → endless defaults fallback.
3. **GPIO7 never configured as input** (BoardPower) — after EXT1 wake the
   pad read 0 forever → `longPressDetected` saw a phantom 5-s hold →
   *every* button wake opened config mode. Short-press UX had never worked.
4. **App config read used envelope offsets** (BLEDeviceConfigurator) —
   `data[150..157]` instead of `body[150..157]`: cfgRange returned
   cfgLIS3DH, every write round-trip scrambled the transport flags
   (TTN keys were safe — their offsets were correct).
5. **BME280 driver** — pressure `var1/2` (datasheet: `/32768`) collapsed
   readings to ~1 hPa; humidity formula wasn't the Bosch algorithm
   (saturated to 255 %); 60 ms blind wait raced the ~58 ms ×8 conversion
   (stale reset values → bogus 11 °C). Now: datasheet formulas, H4/H5
   sign extension, STATUS.measuring poll, plausibility gate.
6. **BLE beacon compile-time gate** — `MINILORA_DEFAULT_BEACON` (off)
   silently overrode the app's toggle; beacon now follows runtime `cfgBLE`
   (Kconfig entry removed).

## LoRaWAN bring-up — SOLVED (evening session)

Chain of root causes, each masking the next (all in `LoRaWanTransport.cpp`):

1. **`radio->begin(5, 0x12, 8)`** — positional-arg nonsense (5 MHz / 18 kHz) →
   `ERR_INVALID_BANDWIDTH -8`, radio never started. Fixed:
   `begin(868.0, 125.0, 9, 5, 0x12, 14, 8)`.
2. **Dangling band pointer** — `new LoRaWANNode(radio, &region, 0)` captured a
   *stack local*; every band read in `createSession()` returned garbage
   (DR=7/FSK, RX2=863.071 MHz, reverted channel masks) → joins failed with
   `ERR_NO_CHANNEL_AVAILABLE -1106`. Fixed: file-scope
   `static const LoRaWANBand_t kLoraBand = EU868;` (v1's `config.h:19` pattern).
3. **Stale RTC state across builds** — `kLoraStateMagic` guard now discards
   nonces/session buffers written by any other build (fresh join instead of
   garbage channel plans).
4. **Task WDT vs RX windows** — join + RX1(5 s network-configured!) blocks
   >5 s; main task now unsubscribes from the WDT for the duration of
   `sendReceive` (`CONFIG_ESP_TASK_WDT_PANIC` is off, so this was only a
   warning, but the reset-button/USB-replug *does* wipe RTC RAM — each of
   those costs one rejoin by design).
5. **THE BIG ONE — FCnt replay** — session buffers were saved *before* the
   data uplink, so `fCntUp` was serialized as 0 (post-join value).
   `getBufferSession()` serializes live counters at call time (LoRaWAN.cpp:507).
   Every restored cycle re-sent FCnt=0 and TTN silently dropped it as a
   replay → "sends once at boot, then never again". Fix: save buffers
   *after* `node->sendReceive()` — captures the incremented `fCntUp` and any
   downlink MAC state.
6. **Diagnostics uplink never sent** — the app calls `sendReceive` twice per
   cycle (telemetry + diag); the second `activateOTAA()` legitimately returns
   `ERR_NONE` ("already activated") which the attempt loop rejected.
   `ERR_NONE` is now accepted.
